# Trends2Targets 進化の計画（2026-10-04〜）

村井さんの依頼（2026-10-04）: 管理（ファイルの整理）・処理の軽量化・予測の根拠の強化・ログと監査の強化・ベイジアン的に学習して精度が上がっていく設計。長期で進めてよい。

## 守ること

- 旧来の計算（Forecast_Agent.js）は新アプリの計算の元（LegacyEngine.js に包む）。旧アプリ・旧スプレッドシートは使わない（2026-10-04 村井さん）。計算を直すときは村井さんの判断を待ち、新アプリだけに公開する。
- 新しい学習は、まず**影で動かす**（今の予測は変えずに、使ったらどうなるかを計り、画面に出す）。予測に効かせるのは、村井さんが承認してから。
- 消さない（ゴミ箱にも送らない）。古いものはアーカイブのフォルダへ移す。
- 段ごとにテストを足し、公開して、版の中身が Git と同じことを確かめる。

## 旧来の計算の直し（2026-10-04 村井さんの依頼で直した。新アプリは @37 で反映。旧アプリ・旧スプレッドシートは使っておらず未リリースのため公開しない）

1. `Number(x || 1)`（Forecast_Agent.js 9281・9287）: 0 を 1 にしてしまい、`auto_update_enabled=0`（自動学習を止める）と補正の係数 0 が効かない。
2. 実績の締まった月の漏れ: 締まった月は予測を実績で置き換えて控える（FORECAST_CLOSED_MONTH_MODE=actual）。締まった後に予測し直すと、検証（B-2）が誤差 0 の行を拾い、自動学習（B-5）に入る。FORECAST_SNAPSHOT に「予測か実績か」の列が無いので、検証の側で除けない。
3. `qual_scale_override` は読むだけで効いていない（5787–5817 はいつも 1）。
4. B-2 の P10/P90 の対応が月だけで引かれ、クライアントで分けていない。

直したこと（Forecast_Agent.js・Forecast_WebApp.js。テスト tests/forecast-calibration-fixes.test.mjs）:
- 1 → `calibrationNumberOr_`: 空は既定値、0 を含む数はそのまま。倍率は正の数だけ（0 以下は 1）。`auto_update_enabled=0` で自動学習（B-5）と C-3 の設定の変更が止まる
- 2 → 新しい予測は FORECAST_SNAPSHOT の key_factors_json に `forecast_source`（actual_closed / forecast_open）を残す。検証（B-2）は `selectEvalSnapshotRows_` で、クライアント × 月ごとに実績が締まる前の最後の予測の回だけを使う（前からの記録は、P50 が実績とまったく同じ回を除く）。EVALUATION_POLICY_VERSION を policy-2026H1-v2 に
- 3 → 予約の列として注記（効かせるには、主観の帯の合わせを設計し直す必要がある。今回は変えない）
- 4 → P10/P90 の対応をクライアント × 月で引く

## 旧アプリを使わないことに合わせた整理（2026-10-04、@38）

- 「旧ブックから移す」画面の、計算の一致の確認（FORECAST.PARITY）と画面の中身の確認（PLAN.VIEW_CHECK）を外した（取り込み・試し読みは残す）。
  データ本体から組み立てた計算用ブックが旧ブックと同じかは、テスト（app-engine の 3・5・6）で直接比べる
- 旧来のコードから、新アプリが呼ぶ関数から名前でたどって届かない 45 の関数（メニュー・ダイアログ・メニュー版の取り込み・管理ハブの POOL 集約・旧 Web アプリの入口など）を除いた。
  道具 `app/tools/engine-usage.mjs`、元は `archive/legacy-2026-10-04/`。届かない関数が残っていないことをテストが確かめる

## 新アプリだけを使うことに合わせた整理と速さ（2026-10-04、@39）

- 速さ: 保存し終えた計算用ブックはデータ本体と同じ中身なので、同じ計画で入力のハッシュが変わっていなければ、次の処理（予測・実行・保存）は組み立て直さずに使う（組み立ては処理でいちばん時間がかかる）。
  使い始めたら控えを消し、保存し終えたら控える。保存の対象より広い範囲を持つときは、ほかのシートがデータ本体と同じか読んで確かめてから広い範囲のまま控える
- データ本体: 毎日の手入れで、使っていない空の行を減らす（セルの上限と、開く・読む時間）・手で直さないよう警告つきの保護・表の種類でタブの色
- 取り込んだ旧ブック: 「旧ブックから移す」画面から、アーカイブのフォルダの「旧ブック」へ移す（消さない）
- 設定: 使っていなかった 8 つ（検証の上限・空模様・操作の記録）を外し、ZAC の実績のスプレッドシートだけに
- 画面: 旧アプリ・新アプリの言い方を外す

## このアプリだけを使う前提での見直し（2026-10-05、@42）

- 「旧ブックから移す」の画面と、旧ブックの試し読み・取り込み（MIGRATION.DRYRUN / MIGRATION.IMPORT、`Migrate.js`）を外した。計画は「計画を作る」だけで作る
- 取り込んだ旧ブックの一覧とアーカイブへ移す操作（LEGACY.BOOKS / LEGACY.ARCHIVE）も外した。旧ブックはそのまま（このアプリは読まない）
- 取り込みの記録の表（IMPORT_BATCHES）は使わない表にした（表の版 8）。前からあるシートは消さずに隠す（中身はそのまま）
- 計画の一覧の「新規」の印（旧ブックから来た計画との区別）と、「取り込んだときの値」などの言い方を外した
- 計算用ブックに書くときの「旧ブックの値と比べる」引数と、旧ブックと比べる関数（appEngCompare_）を外した（比べるのはテストだけ）
- 所有者だけの裏の処理（ownerOnly）は取り込みだけだったので外した
- テストは見本のブックから計画を直接作る（gas-mock の seedPlan）。app-migration は app-codec に（変換・表・裏の処理の仕組み）
- 操作の記録の画面は、外した機能の前の記録も名前で読めるように残す
